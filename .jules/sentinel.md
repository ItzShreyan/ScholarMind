## 2026-07-03 - Open Redirect Vulnerability in Security Verification and Callback Handlers
**Vulnerability:** Untrusted URL redirect validation using `.startsWith("/")` was vulnerable to Open Redirect. Specifically, browsers and standard URL parsers resolve relative URLs starting with multiple slashes (e.g., `///example.com`) or backslashes (e.g., `/\example.com` or `/%5C%5Cexample.com`) to external domains, completely bypassing prefix-based relative checks.
**Learning:** Legacy validation like `url.startsWith("/")` and `url.startsWith("//")` is insufficient because the `URL` constructor and modern web browsers normalize `/\\` and `///` in unexpected ways, treating them as protocol-relative or absolute redirects to external origins.
**Prevention:** Implement a robust `getSafeRedirect` helper that parses the candidate redirect URL against a dummy localhost-based base origin and verifies that the parsed URL's origin remains strictly matched to the dummy base, returning path + search + hash to force a relative redirect.
